# Соглашения контракта

## 1. Названия и версия

Версия располагается только в servers: `/v1/`. Paths содержат `/books`, `/readers`, `/loans`. Составные сегменты, query и sort-токены — kebab-case; JSON-свойства — snake_case. Название ресурса не содержит глагол; `/return` — явно согласованная команда над выдачей.

## 2. Запись ресурса

POST создаёт и возвращает 201 с Location. PATCH обновляет существующий ресурс непустым обычным JSON-объектом и возвращает 200. Отсутствующие поля не меняются, null запрещён в изменяемых полях. DELETE возвращает 204 без тела. PUT не включён: частичное обновление достаточно для CRUD этой модели.

## 3. Направление схем

Request-схемы перечисляют только клиентские поля и запрещают additionalProperties. Response-схемы допускают дополнительные поля; клиент их игнорирует. readOnly — вспомогательная аннотация, не замена отдельной request-схеме. Resource ID — положительный int32, назначаемый сервером.

## 4. Обработка отказов

ErrorResponse плоский: code, message, request_id, violations. В violation указываем location, pointer, rule, message. Для тела pointer — JSON Pointer. message предназначено человеку, rule — диагностике; не разбираем текст сообщения программно. Синтаксис/параметры — 400, авторизация — 401, отсутствие — 404, конфликт — 409, семантика тела — 422, неверный media type — 415.

## 5. Работа со списком

Всегда возвращаем items и page. page-size по умолчанию 25, максимум 50. next_cursor=null на последней странице; has_next эквивалентен next_cursor!=null. Не публикуем total и offset. Cursor непрозрачен, подписан, связан с субъектом/endpoint/фильтрами/sort/page-size, живёт 30 минут от начала прохода. Не обещаем снимок каталога между запросами.

## 6. Порядок элементов

sort — comma-separated массив токенов. Направление DESC обозначается минусом. Порядок токенов задаёт приоритет; ID всегда завершает порядок, автоматически добавляясь как ASC, если его нет. Одно поле нельзя указывать дважды. Фильтры объединяем AND; q внутри текстовых полей работает через OR.

## 7. Календарь и остаток

Даты — YYYY-MM-DD по UTC, моменты времени — RFC 3339, ответ с Z. due_date новой выдачи строго больше текущей даты. overdue означает returned_at=null и due_date<сегодня, срок сегодня не просрочен. available_copies вычисляется из фонда и активных выдач, никогда не принимается от клиента.

## 8. Транзакционные границы

Выдача проверяет доступный экземпляр и квоту читателя в одной атомарной операции с записью. Изменение фонда и удаление также согласуются с выдачами. Повторный возврат не меняет returned_at и не повышает остаток повторно. DELETE книги/читателя логический и запрещён при активных выдачах.

## 9. Повторы и доступ

Каждый запрос требует Bearer JWT; проверка предшествует replay. POST /loans требует Idempotency-Key с областью по JWT sub/методу/пути. Фиксируем fingerprint, replay байтов/статуса/всех заголовков, mismatch, ожидание конкурентного запроса и TTL 24 часа от завершения. Новая логическая выдача — новый ключ, транспортный повтор — прежний.

## 10. Качество описания

Каждая операция имеет operationId, tag, summary, description и явные статусы. Examples валидируем; `$ref` проверяем. Динамические условия не выдаём за возможности JSON Schema. Изменение wire-контракта сопровождаем анализом совместимости; прохождение JSON Schema-тестов не называем полноценной проверкой генератора SDK.
