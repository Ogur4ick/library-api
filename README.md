# Контракт библиотеки: каталог и выдачи

Проект содержит описание OpenAPI 3.1 и документы, необходимые для сдачи урока №3. Это проект API, не серверная реализация. Он использует cursor-пагинацию, числовые resource ID, PATCH для Update и JWT для доступа.

## Состав проекта

| Файл | Назначение |
| --- | --- |
| openapi.yaml | Машинный контракт: 14 операций, схемы, параметры, ответы и примеры |
| STYLE.md | 10 правил проектирования |
| REVIEW.md | Самопроверка по материалам урока и рубрикатору |
| README.md | Обоснование решений, сценарии и запуск проверки |

## Решения и их цена

| Решение | Обоснование | Ограничение |
| --- | --- | --- |
| Числовой ID int32 | Простое представление в URL и моделях учебного сервиса | ID раскрывает приблизительный порядок регистрации; не является средством авторизации |
| PATCH без PUT | Для изменения имени/фонда достаточно частичной правки | Полная замена не предусмотрена; клиент отправляет только меняемые поля |
| Keyset cursor | Продолжение по сортировочному ключу вместо позиции offset | Нет перехода на «страницу 17» и точного total; правки сортируемых полей между страницами могут изменить выдачу |
| Множественная сортировка | Позволяет сортировать книги по автору, затем названию | Требует валидации повторных полей и строгого последнего ключа ID |
| Плоский ErrorResponse | Код отказа находится непосредственно в корне ответа | Отличается от envelope-вариантов; клиенты должны следовать этой схеме |
| Расширяемые ответы, закрытые запросы | Можно добавлять необязательные response-поля, не принимая опечатки в request | Клиент обязан игнорировать неизвестные response-поля; изменение типов/required остаётся breaking |
| JWT и scope по sub | Разделяет ключи повторов разных субъектов | Появляется зависимость от провайдера токенов; ролевое разграничение не спроектировано |
| Логическое удаление | Сохраняет историю выдач | Не является выполнением требований физической очистки персональных данных |

`isbn` принимает компактный ISBN-10 или ISBN-13 с проверкой контрольной суммы. Значения двух форматов не конвертируются друг в друга: это осознанное упрощение уникальности, не полноценный каталог библиографических идентификаторов.

## Ресурсная карта

| Ресурс | Операции |
| --- | --- |
| Books | GET/POST /books; GET/PATCH/DELETE /books/{id} |
| Readers | GET/POST /readers; GET/PATCH/DELETE /readers/{id} |
| Loans | GET/POST /loans; GET /loans/{id}; POST /loans/{id}/return |

Базовые URL заканчиваются `/v1/`. Продакшен-адрес иллюстративный; локальный адрес — http://localhost:8080/v1/. Ни один из них не запускается автоматически.

Все операции требуют Bearer JWT, который выдаёт внешний провайдер. Подпись, алгоритм, issuer, audience, exp/nbf и sub проверяет сервер. Валидный токен даёт доступ ко всем учебным операциям; наличие JWT само по себе не описывает роли или политики доступа.

## Сценарий просмотра

Для первой страницы передайте фильтры и sort, но не cursor:

```bash
curl -i 'http://localhost:8080/v1/books?in-stock=true&sort=author,title&page-size=25'   -H "Authorization: Bearer $TOKEN"
```

Если page.has_next=true, возьмите page.next_cursor и отправьте его с теми же параметрами и тем же субъектом JWT. Токен непрозрачен: не декодируйте/не редактируйте его. Ограничение прохода — 30 минут с первого cursor, без продления.

```bash
curl -i --get 'http://localhost:8080/v1/books'   -H "Authorization: Bearer $TOKEN"   --data-urlencode 'in-stock=true'   --data-urlencode 'sort=author,title'   --data-urlencode 'page-size=25'   --data-urlencode "cursor=$CURSOR"

curl -i 'http://localhost:8080/v1/loans?status=overdue&sort=due-date&page-size=25'   -H "Authorization: Bearer $TOKEN"
```

Сортировка author,title фактически заканчивается id ASC. Курсор не обещает неизменность каталога. Для overdue календарная дата фиксируется при первой странице, чтобы полночь не меняла границу просрочки в одном проходе.

## Сценарий выдачи и возврата

После создания книги и читателя используйте реальные числовые ID. Установите TOKEN на действующий JWT своей реализации, BOOK_ID и READER_ID на возвращённые ID. Команды предполагают bash и Python 3; они демонстрационные, не свидетельствуют о запущенном сервере.

```bash
BOOK_ID=101
READER_ID=501
KEY=$(python3 -c 'import secrets; print(secrets.token_hex(16))')
DUE_DATE=$(python3 -c 'from datetime import datetime, timezone, timedelta; print((datetime.now(timezone.utc).date()+timedelta(days=21)).isoformat())')
BODY=$(printf '{"book_id":%s,"reader_id":%s,"due_date":"%s"}' "$BOOK_ID" "$READER_ID" "$DUE_DATE")

curl -i -X POST 'http://localhost:8080/v1/loans'   -H "Authorization: Bearer $TOKEN"   -H "Idempotency-Key: $KEY"   -H 'Content-Type: application/json'   --data "$BODY"
```

Повторите запрос с теми же BODY/KEY и действующим JWT того же sub до истечения 24 часов: получите исходный статус, байты тела и все заголовки. Измените BODY при прежнем KEY — получите 409 IDEMPOTENCY_MISMATCH. Если исходный запрос выполняется, повтор может ждать до 2 секунд; затем возвращает replay либо 409 CONFLICT/request_pending с Retry-After: 2.

После создания возьмите ID Loan (901 здесь — только пример):

```bash
curl -i -X POST 'http://localhost:8080/v1/loans/901/return'   -H "Authorization: Bearer $TOKEN"
```

Возврат не принимает тело и не требует ключа. Повтор — 200 с прежним returned_at. Loan остаётся в истории.

Статические examples используют 2028 год; живая due_date всегда выбирается относительно текущей даты сервера. JSON Schema проверяет формат, но не выражает «завтра», остаток фонда, квоту и транзакции.

## Приёмочные сценарии

| Сценарий | Ожидаемый результат |
| --- | --- |
| Передать available_copies в POST/PATCH Books | 422 VALIDATION_ERROR, unknown_property |
| Выдать при available_copies=0 | 409 BUSINESS_RULE_VIOLATION, stock_exhausted |
| Оформить шестую активную выдачу | 409 BUSINESS_RULE_VIOLATION, active_loan_quota |
| Передать due_date сегодня UTC | 422 VALIDATION_ERROR |
| Одновременно оформить две выдачи последнего экземпляра с разными ключами | Не более одной успешной выдачи |
| Удалить книгу/читателя с активной выдачей | 409 BUSINESS_RULE_VIOLATION |
| Вернуть одну выдачу дважды/параллельно | 200 в обоих успешных ответах; returned_at один и тот же |
| Повторить завершённую выдачу с ключом и телом | Полный replay без нового Loan |
| Отправить другое тело с ключом, ещё находящимся in-progress | 409 IDEMPOTENCY_MISMATCH, не request_pending |
| Повторить исходный ключ после completed_at+24h | Новый запрос; replay больше не гарантируется |
| Повторить запрос с истёкшим JWT | 401; новый действующий JWT того же sub сохраняет scope |
| Изменить фильтр/page-size при передаче cursor | 400 INVALID_REQUEST |
| Получить пустую коллекцию | 200, items=[], has_next=false, next_cursor=null |

Таблица задаёт ожидаемое поведение backend. Сам backend не реализован, поэтому эти сценарии не выданы за выполненные интеграционные тесты.

## Проверка и генерация

При сборке выполнены разбор YAML, разрешение внутренних ссылок, проверки JSON Schema-компонентов и examples, негативные schema-тесты. Внешний lint, генератор SDK и mock не запускались; успешная схема не гарантирует поддержку всех возможностей конкретным генератором.

```bash
npx @redocly/cli lint openapi.yaml
```

Для ранее наблюдавшейся Windows-ошибки парсинга абсолютного пути запускать генератор можно через локальный HTTP URL вместо E:\... . PowerShell, первое окно:

```powershell
Set-Location 'E:\projects\PycharmProjects\library-api'
python -m http.server 8090 --bind 127.0.0.1
```

Второе окно; путь к JAR задайте фактический:

```powershell
$jar = 'C:\tools\openapi-generator-cli.jar'
java -jar $jar generate -g python -i 'http://127.0.0.1:8090/openapi.yaml' -o 'C:\Users\Андрей\gen-alternative'
```

Этот HTTP-сервер раздаёт только файл спецификации, не реализует Library API и не является mock. jsonSchemaDialect в контракте отсутствует; возвращать предупреждавшее нестандартное значение не требуется.

## Дополнительное задание

Выполнен пункт Bearer JWT: components.securitySchemes.AccessToken задаёт type=http, scheme=bearer, bearerFormat=JWT; глобальный security применяет схему ко всем 14 операциям. На каждой операции предусмотрен 401 с единым ErrorResponse и WWW-Authenticate. Эндпоинт выпуска токенов не входит в задание.
